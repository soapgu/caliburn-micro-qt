## 1. 交付范围

- ShellViewModel 增加 `Q_INVOKABLE void add(int delta)`，只接受正增量且结果不超过 5；先比较剩余额度再相加，拒绝零、负数、越界及极大值，不产生状态变化或通知。increment() 复用 add(1)，reset() 保留原行为。
- 增加只读 `canAddTwo` 与 `canAddTwoChanged`，计数 0～3 时成立，bool 结果变化时才通知。“加 2”按钮显式绑定此属性并调用 add(2)。
- 页面 Item 处理无修饰数字键 2，使用 Keys.AfterItem，过滤自动重复；成功处理才设置 event.accepted，不处理的事件继续传播。
- 初始焦点在页面；TextField 获得焦点时优先消费数字输入，点击空白处返回页面。Tab / Shift+Tab 显式在增加、加 2、重置和文本框之间移动，跳过禁用项；按钮原生空格点击保持可用。
- 新按钮与键盘处理器读取当前 viewModel，替换后通知和操作均跟随新 VM，旧 VM 不影响界面。

没有新增框架类型、输入适配层、生命周期、业务服务、导航或弹窗。未修改其他仓库，未暂存、提交或推送。

## 3. 实际示例操作

单独启动本次 `build/parameters-keyboard/bin/CaliburnExampleApp.app`，通过原生界面操作并读取文字、按钮状态和焦点：

| 操作 | 实际结果 |
| --- | --- |
| 启动 | 显示“已点击 0 次”，增加与加 2 可用，重置禁用。 |
| 点击加 2 | 显示“已点击 2 次”，重置可用。 |
| 按数字键 2 | 显示“已点击 4 次”，加 2 禁用。 |
| 再按数字键 2 | 仍为 4，没有越界或额外更新。 |
| 点击重置 | 回到 0，加 2 恢复，重置禁用。 |
| 点击文本框并按 2 | 文本框输入“2”，计数仍为 0。 |
| Tab 后按空格 | 焦点移到增加按钮，计数为 1。 |
| 按数字键 2 | 按钮未消费的按键由页面处理，计数为 3。 |
| 再按数字键 2 | 计数为 5，增加与加 2 均禁用。 |
| 关闭 | 验收窗口关闭。 |

实际窗口操作与自动测试分别完成；实体键盘长按未单独计时验收，自动重复路径已在 offscreen 和 Cocoa 中验证。截图检查默认窗口布局，文字、按钮、文本框及焦点边框均正常显示。

## 4. 实施修正与限制

焦点回归发现 FocusScope.forceActiveFocus 会保留其子文本框焦点，页面改为普通 Item 后空白点击可回到页面。Cocoa 的默认 Tab 行为会跳过按钮，因此用 Qt 原生 KeyNavigation 显式设置顺序；BeforeItem 仅用于 Tab 导航，数字键业务处理保持 Keys.AfterItem。

Qt 构建和测试在沙箱外执行，沿用第一批对 arm64 特性检测问题的处理。链接器仍报告静态插件重复库提示，Cocoa 出现系统输入法 mach port 日志；构建和最终测试均正常。仅框架构建沿用第一批证据，本批没有改变框架源码或依赖；未将其记录为本次重新验收。
