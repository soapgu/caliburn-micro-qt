# 链接依赖清理验收记录

2026-10-09，macOS arm64、Qt 6.8.3、CMake 3.30.5、Ninja。先使用独立构建目录复现，再修改测试与 App 链接配置。历史验收记录中的重复库提示描述保留为当时结果；当前状态以本记录为准。

## 诊断

干净构建产生 7 条 `ld: warning: ignoring duplicate libraries`。通过 `ninja -t commands` 逐项统计实际链接命令，定位如下：

| 目标 | 修改前重复项 | 修改后 |
| --- | --- | --- |
| CaliburnExampleApp | 两个插件库各出现 2 次 | 两个插件库各 1 次 |
| CaliburnQmlTests、CaliburnBootstrapperTests、CaliburnDialogTests | 框架插件库各出现 2 次 | 框架插件库各 1 次 |
| CaliburnParentProtocolTests、CaliburnCollectionTests、CaliburnConductorTests | 框架库各出现 2 次 | 框架库各 1 次，无插件链接 |

App 的两个插件、三个 QML/Bootstrapper/Dialog 测试的框架插件，同时来自显式 target_link_libraries 和 Qt 导入扫描。三个纯 C++ 测试直接链接框架库，但 qt_add_executable 的自动扫描又加入框架插件；插件依赖 backing library，框架库再次进入链接命令。

Qt 6.8.3 本机 Qt6QmlMacros.cmake 中，qt6_import_qml_plugins 将扫描到的静态插件加入最终目标；qt_add_qml_module 生成的插件链接对应 backing library。DEPENDENCIES TARGET 声明模块依赖及构建顺序，不替代 C++ target_link_libraries 的使用要求。因此保留示例模块的 PUBLIC Caliburn::MicroQt 链接。

## 修改

- App 删除两个显式插件链接，沿用 Qt 自动扫描结果。
- QML、Bootstrapper、Dialog 测试删除显式框架插件链接。扫描结果未包含通过动态 URL 加载的示例插件，仍保留 CaliburnExampleModuleplugin。
- ParentProtocol、Collection、Conductor 测试使用普通 add_executable，保留直接框架链接；测试不加载 QML，无需自动导入插件。
- App 和 QML 测试保留 Q_IMPORT_QML_PLUGIN，模块 DEPENDENCIES、资源及类型注册配置保持原有行为。
- CI 保存完整 build.log，出现 ignoring duplicate libraries 时使编译步骤失败，并上传日志。未添加链接器警告抑制参数。

## 验证

Qt 构建及测试在沙箱外运行，沿用本机预设，避免已知的沙箱 NEON 检测限制。

```sh
# 修改前：新目录全量构建，保存基线日志。
cmake --preset macos-local -B /private/tmp/cmqt-link-cleanup
cmake --build /private/tmp/cmqt-link-cleanup -j 4

# 修改后：自动重新配置，并重新链接所有受影响的目标。
cmake --build /private/tmp/cmqt-link-cleanup -j 4
ctest --test-dir /private/tmp/cmqt-link-cleanup --output-on-failure -j 4
cmake --build /private/tmp/cmqt-link-cleanup --target all_qmllint -j 4

cmake --preset macos-local -B /private/tmp/cmqt-link-framework-only \
  -DCALIBURN_BUILD_EXAMPLE=OFF -DCALIBURN_BUILD_TESTS=OFF
cmake --build /private/tmp/cmqt-link-framework-only --target all all_qmllint -j 4
```

| 检查 | 结果 |
| --- | --- |
| 修改前基线 | 全量构建成功，7 条重复库警告 |
| 修改后构建 | 所有 7 个受影响目标重新链接成功，重复库警告为 0 |
| 实际链接命令 | 全部 11 个可执行目标中，每个项目静态库只出现 1 次 |
| CTest | 27/27 通过，包含 qrc 资源加载、QML 类型注册、Bootstrapper 启动及弹窗测试 |
| all_qmllint | 框架与示例均通过 |
| 仅框架构建与 all_qmllint | 通过 |
| CI 日志检查 | 真实基线日志退出码 1，修复后日志退出码 0；工作流 YAML 解析通过 |
| git diff --check | 通过 |

基线与修复后构建日志分别保存于 /private/tmp/cmqt-link-baseline.log 和 /private/tmp/cmqt-link-after.log，测试、qmllint 及仅框架日志使用同目录下的 cmqt-link-* 文件。本地临时日志不纳入仓库。

故意非法的 SyntaxError.qml 夹具仍产生预期扫描诊断。本轮未运行远端 CI、Linux/麒麟或原生窗口人工操作；本地插件和动态资源加载由已有自动测试验证。
