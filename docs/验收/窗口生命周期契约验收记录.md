# 窗口生命周期契约验收记录

验收日期：2026-11-12。基线提交：`c2bba3ac5815da900eb54640cbe8e52bc75da158`。对应 [IoC 改造方案](../IoC改造方案.md)第 3 步。

## 接口与变更边界

新增公开头文件 `CaliburnMicroQt/IWindowManagerLifecycle.h`。接口为普通 C++ 类，声明 Qt 接口标识 `Caliburn.Micro.Qt.IWindowManagerLifecycle/1.0`，不继承 QObject，不注册 QML 类型。

| 方法 | 契约 |
| --- | --- |
| prepareForShutdown() | 结束在途弹窗，解除交互关联，保留普通 View |
| releaseWindows() | 释放窗口、View、引擎和模型借用，不删除借用 VM |
| subscribeWindowCleanupFailed(context, callback) | 同线程通知，返回可断开的连接，并绑定 context 寿命 |

WindowManager 自身多重继承新接口并声明 Q_INTERFACES，两个原清理方法仅增加 override。新增订阅方法检查空 context、空回调和跨线程 context，非法参数返回无效连接；合法订阅使用 Qt::DirectConnection 连接既有 windowCleanupFailed 信号。

所有方法须在服务所属线程调用。回调不得抛异常、销毁服务或重入清理。订阅在 context 或服务销毁后失效，可由调用方主动断开。

同一服务对象同时提供窗口与生命周期能力，通过 qobject_cast<IWindowManagerLifecycle*> 查询，不引入独立生命周期适配器或身份配对方法。IWindowManager 未新增纯虚方法，旧实现不需要实现新接口。

既有清理方法体、窗口状态和释放顺序未修改；未新增永久关闭状态，未修改 Bootstrapper 的成员、调用或信号连接，未接入实例提供器。

## 测试覆盖

在既有 `windowmanager` CTest 项中增加 4 个方法，复用原 WindowProbe、DialogProbe 和窗口清理夹具，不新增 CTest 项。

| 方法 | 覆盖及结果 |
| --- | --- |
| lifecycleCapabilityAndLegacyService | 从 IWindowManager 指针查询接口并校验同一对象；新增只实现旧接口的 LegacyWindowManager，确认能力查询为空，旧窗口及弹窗调用仍可使用 |
| lifecyclePreparationAndRelease | 经接口准备退出，弹窗窗口同步释放、Future 完成、busy 清空、VM 延迟回收；主辅普通 View 与借用 VM 保留；最终释放窗口不删除 VM；重复清理不重复执行关闭生命周期 |
| lifecycleFailureSubscriptions | 辅助 VM 关闭抛异常时，原信号和有效订阅各收到一次通知；已主动断开及已销毁 context 的订阅不执行；主辅窗口继续释放；重复清理不重复通知或关闭 |
| lifecycleInvalidSubscriptionsAndServiceDestruction | 空 context、空回调和跨线程 context 返回无效连接；服务销毁后连接失效，事件处理后没有残留回调 |

原测试替身 TestWindowManager 继承默认 WindowManager，因此会继承新能力，不能用于证明旧实现兼容。LegacyWindowManager 仅在本测试源码中定义，不继承默认实现，也不声明新接口。

首次定向执行发现新增测试错误地要求弹窗 VM 同步销毁。核对 WindowManager::finish() 后确认既有实现先同步释放窗口及 View，再安排 VM deleteLater，最后完成 Future。仅将测试修正为同步断言窗口和状态、以 QTRY_VERIFY 等待 VM 回收，生产实现不变。修正后定向测试通过；这不是生产缺陷。
