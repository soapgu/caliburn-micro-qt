# 根窗口关闭守卫与生命周期验收记录

2026-10-10，基于 HEAD `d3eb785` 实施根窗口守卫、根 VM 双向关闭桥接与 Bootstrapper 钩子对齐。已完成 macOS arm64 本机验收；麒麟与外部消费工程待验证。历史验收记录保持原样。本轮未暂存、提交或推送。

## 交付与接口变更

- 私有 WindowConductor 由 Bootstrapper 持有，以 QPointer 借用根窗口和根 Screen，不改变 QObject 所有权或逻辑 Parent。根 View 加载及 DialogHost 挂载成功后安装桥接。
- 窗口首次关闭立即拒绝原事件，排队执行根 canClose，退出原关闭调用栈后才恢复关闭。等待期间重复窗口关闭不新增检查；拒绝保留窗口和页面。恢复关闭跳过桥接守卫，Qt/QML 原有关闭处理仍可拒绝；只有 window.close() 成功且窗口已关闭，才发出窗口完成通知并执行 CloseRoot。
- Screen 新增 closeRequested 信号，只表达请求。tryClose 有 Conductor Parent 时继续委托；无逻辑 Parent 时发出请求，由关联窗口桥接执行关闭；非 Conductor Parent 或没有窗口桥接时不执行关闭。
- 根直接完成 deactivate(true) 后，桥接排队关闭窗口且跳过守卫；普通停用不关闭窗口。窗口关闭完成标志在根生命周期之前提交，防止完成信号再次关闭窗口。延后操作检查对象存活，解除桥接后迟到许可无操作。
- Bootstrapper 的 OnStartup 从 bool 改为默认空实现的 void，OnExit 保持默认空实现的 void。Configure 成功并冻结映射后调用 OnStartup，显示记录和异常决定启动成败；空钩子、显示失败、重复显示均不能视作成功启动。
- 正常 aboutToQuit 依次停用桥接、CloseRoot、OnExit，此时根 VM 和 QML 对象仍存活。根 attemptingDeactivation(true) 记录外部直接关闭尝试；OnExit 在调用前记录已通知。关闭钩子或退出钩子异常被记录，清理继续执行且不重试。
- 事件循环返回后最终 Shutdown 释放桥接、引擎/View、根 VM 与服务；失败且未经过退出通知时补调一次 OnExit。基类析构只兜底释放，不调用派生退出钩子。
- Detail 返回和整窗关闭共用“离开详情／确定离开当前详情吗？”确认，仅 true 同意。根关闭检查 Shell 全部成员，包括非活动 Detail；提交根生命周期，不调用成员关闭准备钩子，不补 Home。

接口迁移及当前契约见 [Bootstrapper](../Bootstrapper.md)、[Screen](../ScreenViewModel.md) 和 [关闭守卫](../关闭守卫.md)。业务的 bool OnStartup 重写须迁移为 void；OnExit 从事件循环返回后前移至 aboutToQuit，须兼容部分初始化与启动失败。

## 环境与命令

macOS arm64、Qt 6.8.3、C++17、Debug、Ninja。使用已有 macos-local 预设和独立目录，Qt 工具在沙箱外执行，未修改本机预设。

```sh

cmake --build /private/tmp/cmqt-root-window-build -j 4
ctest --test-dir /private/tmp/cmqt-root-window-build --output-on-failure -j 4
cmake --build /private/tmp/cmqt-root-window-build --target all_qmllint -j 4
cmake --preset macos-local -B /private/tmp/cmqt-root-window-framework-only -DCALIBURN_BUILD_EXAMPLE=OFF -DCALIBURN_BUILD_TESTS=OFF

QT_QPA_PLATFORM=cocoa QT_QUICK_BACKEND=software /private/tmp/cmqt-root-window-build/tests/CaliburnWindowConductorTests
QT_QPA_PLATFORM=cocoa QT_QUICK_BACKEND=software /private/tmp/cmqt-root-window-build/tests/CaliburnDialogTests
QT_QPA_PLATFORM=cocoa QT_QUICK_BACKEND=software /private/tmp/cmqt-root-window-build/tests/CaliburnQmlTests
```

根窗口集成数据行也分别使用 Cocoa 在独立进程执行。CTest 采用既有 offscreen/software 环境；Qt Test 条数包含 init/cleanup 与数据行，不表示断言数量。

## 实际窗口交互

使用最终构建 `/private/tmp/cmqt-root-window-build/bin/CaliburnExampleApp.app`，通过原生窗口与系统菜单操作验证：

- Home 加 2 后显示 2；文本框输入 2 不增加计数；Detail 展示共享计数 2，Home 保留初始化状态且不活动。
- 点击标题栏关闭出现中性详情确认，默认焦点在取消。Escape 和取消均保留详情与窗口；再次关闭并确认，整个窗口与应用退出。
- Detail 中 Cmd+Q 弹出同一确认；取消后应用继续运行，再次 Cmd+Q 并确认后退出。系统应用菜单的 Quit CaliburnExampleApp 也进入确认，接受后退出。
- 返回首页按钮共用确认；接受后 Home 恢复活动，Detail 无页面，计数仍为 2，新的 Home View 文本框为空。
- 返回后页面数字键 2 将计数增加到 4；文本框输入 2 不增加计数。重置接受后计数归零，焦点恢复到原文本框，文本仍为 2。
- 仅有 Home 时标题栏关闭直接退出，不出现详情确认。

根 tryClose 和根直接关闭路径通过 Cocoa 真实窗口集成测试验证；示例未为验收增加专用业务按钮。

## 范围与限制

保持单根窗口和默认最后窗口关闭退出行为。普通 Qt Quit、菜单退出与 Cmd+Q 经过窗口关闭路径；直接 QCoreApplication::exit 或失败清理只执行一次生命周期和退出钩子，不补交互守卫。系统强制终止交互、多窗口退出协调与 View 缓存未实现。

Conductor 继续采用此前确认的 CM 直接回调契约；未重新加入通用 Request、代次、请求队列或并发协调。窗口桥接只保留等待许可、恢复关闭及双向防循环所需状态。守卫与同步生命周期的框架异常传播约定不变；Qt 事件与异步业务边界记录异常，已提交状态不回滚。
