## 专项与集成覆盖

`tests/cpp/tst_viewlocator.cpp` 的配置隔离场景按 CTest 数据行运行于独立进程，不为生产接口增加 reset。覆盖：

- 命名转换、后缀不匹配和空基本名；同命名空间、ViewModels 映射、功能子层级与最后一个 ViewModels 段。
- 完整前缀边界、前缀及目录大小写、多根组间优先级、组内根顺序和重复配置；qrc 与本地临时目录。
- 显式登记及默认优先级、缺失覆盖不回退、重复登记、冲突、非法 URL / 根 / 目录 / 前缀、资源缺失、冻结、空模型及非法线程。不沿基类映射回退，查询不冻结，也不缓存结果。
- 直接继承 QObject 的 PreviewViewModel，通过显式与约定定位装入 ViewHost；typed 注入、NOTIFY 刷新且 View 身份不变、同类型替换重建、旧模型销毁不影响新模型、当前模型销毁清空宿主，以及错误类型注入拒绝。
- 选定文件语法错误、非 Item 根、注入失败及显式地址缺失时均不切换到已有的其他候选。

既有 QML 套件改用示例搜索根，验证不同引擎独立单例共享定位配置。DialogTests 的 CustomDialogViewModel 保持 Screen 类型，改走约定定位并继续验证结果和 View 先于 VM 销毁。Bootstrapper、WindowManager、页面导航、确认、关闭守卫与日志回归均包含在全部 CTest 内。

## 统一定位规则调整（2026-10-13）

删除 Registry 对 ConfirmActionViewModel 的精确默认映射及相关类型依赖。Registry 仅保存显式登记；所有类型统一按“显式映射 → 约定搜索”定位。Locator 初始化时包含框架根 `qrc:/qt/qml/Caliburn/Micro/Qt/`，不依赖 Bootstrapper；应用根按添加顺序插入框架根之前。各根共用候选生成和存在性检查，继续先查所有根的 Views 映射候选，再查所有根的同命名空间候选，同组中框架根最后。

内置 ConfirmActionView.qml 资源地址与公开 QML 类型保持。应用可通过显式登记或匹配搜索根下的同名 QML 覆盖内置视图。ConfirmActionViewModel 位于全局命名空间，限定应用命名空间的根不能覆盖它，可另加空前缀根。文件缺失继续搜索；显式地址缺失，或选定文件后出现加载、根类型及注入失败，均不回退其他候选。

新增 6 个独立进程确认弹窗场景，并增强原显式覆盖、缺失覆盖及日志用例：

- `convention`：应用 qrc 根的 views/ConfirmActionView.qml 约定定位，typed 注入及确认、取消结果正确。
- `flat`：应用同命名空间候选先于框架同类候选命中。
- `missingRoot`：应用文件缺失后命中内置确认视图。
- `restricted`：限定前缀的根不匹配全局类型；另加空前缀根后成功覆盖。
- `broken` / `wrongType`：应用文件已命中，但语法或注入类型错误；请求交付异常、清除 busy，不回退内置视图。
- `override` / `missing`：存在可用应用约定候选和框架候选时，显式映射仍优先，缺失显式资源不回退。
- 定位专项验证无应用配置时内置根可用、重复添加内置根幂等，以及随后添加应用根仍能覆盖。Debug / Release 日志断言确认内置视图使用 Convention view found 诊断。
