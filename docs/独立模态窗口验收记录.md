## 交付行为

- 用模块内部 DialogWindow 包装业务 Item View，创建独立 QQuickWindow，配置 Qt::Dialog、所属窗口 transientParent 和 Qt::ApplicationModal。不再向主窗口内容树插入 Popup.Item，未引入 Widgets。
- 保留 QFuture<std::optional<bool>>、单弹窗与忙拒绝。守卫内部再请求弹窗也按忙状态拒绝，不实现嵌套模态窗口或同步事件循环。
- 按钮结果、标题栏、Escape、弹窗 tryClose 共用 WindowConductor 守卫；拒绝或 QML veto 保留窗口和 VM，丢弃本次结果，Future 不完成。
- 生命周期直接关闭后反向关闭窗口，普通停用不关闭；实际关闭后先卸载、销毁 View，再执行最多一次关闭生命周期并安排 VM 延迟删除，最后完成 Future。
- 请求者、VM、窗口、引擎和服务失效，解除关联与退出均有强制清理。VM 销毁续接绑定旧窗口，窗口释放后不影响下一次请求。
- Bootstrapper 退出时先停用桥接并结束弹窗，再处理根生命周期和 OnExit；退出钩子中确认弹窗 Future 已结束。
- 移除 DialogHost、DialogHostState 手动宿主接口；attachToWindow 改为登记所属窗口、引擎和后备焦点。迁移要求见 [窗口服务](WindowManager.md)。

## 实际 Cocoa 窗口交互

使用本轮生产代码构建的 `/private/tmp/cmqt-modal-build/bin/CaliburnExampleApp.app`，通过原生应用 UI 验证：

- Home 加 2 显示 2；打开重置时出现独立“对话框”窗口，默认聚焦取消。Escape 保留计数，接受后归零，主窗口继续打开。
- 文本框输入 2 仅改变文本，不增加计数；重置接受后原文本框恢复焦点，文本仍为 2。
- 进入 Detail 展示共享计数 2；返回确认通过独立窗口展示。关闭确认框标题栏保留 Detail，接受后回到 Home，计数仍为 2，新的 Home View 文本为空。
- Detail 中主窗口标题栏关闭触发确认；取消后主窗口和 Detail 保持活动。
- Cmd+Q 触发同一确认，Escape 拒绝退出后继续显示 Detail。应用菜单 Quit 也触发确认，接受后全部窗口关闭，应用清单确认进程不再运行。
- 根 tryClose、直接根关闭、普通停用及强制 exit 路径通过 Cocoa 集成测试验证，未增加验收专用业务按钮。

## 调试结论与边界

VM 意外销毁时，ViewHostState 的 QPointer 可先清空；仅再次设置空 model 不一定触发 Loader 卸载。最终通过窗口父树统一释放 View/Loader，避免手动删除仍由 Loader 引用的 View；VM 销毁清理绑定旧窗口，外部窗口销毁清理绑定旧桥接，等待析构完成再关闭 VM。回归断言覆盖正常与强制清理时 View 先于关闭生命周期，以及旧清理不能关闭下一弹窗。

Escape 使用窗口级 Shortcut，避免依赖业务 Item 父链是否继续传播该键。独立窗口的曝光、激活及关闭均为事件驱动，测试已迁移为向实际窗口发送输入并等待真实完成，不沿用窗口内 Popup 的同步假设。

最终清理修复后，重新执行全量 CTest、两个构建配置的检查、全部 20 个 Cocoa 入口，以及实际窗口加计数、重置 Escape、Detail 返回接受和 Cmd+Q 接受回归。Cocoa 过程中曾有一次窗口激活等待超时，独立场景及整组复跑通过，最终串行复验 20/20 通过。验收工具读取已退出实例时重新打开过示例，额外实例已关闭。
