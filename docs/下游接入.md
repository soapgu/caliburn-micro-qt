# 下游源码接入

框架以静态 QML 模块提供源码接入，公开 C++ 目标为 `Caliburn::MicroQt`，QML URI 为 `Caliburn.Micro.Qt 1.0`。Qt 自身可以使用动态库。当前不提供 `find_package(CaliburnMicroQt)` 安装包、安装导出或可直接分发的独立应用包。

## 独立消费工程

[`examples/standalone`](../examples/standalone) 是独立 CMake 项目，不由框架顶层加入构建。它包含自己的 Shell/Home VM、QML 模块、Bootstrapper 和集成测试，只通过公开头文件和 `Caliburn::MicroQt` 使用框架，不链接 `CaliburnExampleModule`、Boost.Ext.DI 或 spdlog。

需要 Qt 6.8.3 及以上、CMake 3.21 及以上、Ninja、C++17 编译器；运行集成测试另需 Qt Test。Qt Creator 打开该目录自己的 `CMakeLists.txt`，选择 Qt 6 Kit，运行 `CaliburnConsumerApp`。关闭 `BUILD_TESTING` 可只构建消费应用。

以下命令刻意将消费工程复制到仓库外，避免依赖示例的相对目录、旧构建产物或工作目录。`QT_ROOT` 指向当前平台的 Qt kit，`CALIBURN_SOURCE` 指向框架仓库的绝对路径：

```bash
cmake -E copy_directory "$CALIBURN_SOURCE/examples/standalone" "$CONSUMER_SOURCE"
cmake -S "$CONSUMER_SOURCE" -B "$CONSUMER_BUILD" -G Ninja \
  -DCMAKE_PREFIX_PATH="$QT_ROOT" -DCMAKE_BUILD_TYPE=Debug \
  -DCALIBURN_SOURCE_DIR="$CALIBURN_SOURCE" \
  -DFETCHCONTENT_FULLY_DISCONNECTED=ON
cmake --build "$CONSUMER_BUILD" --parallel 4
cmake --build "$CONSUMER_BUILD" --target all_qmllint
ctest --test-dir "$CONSUMER_BUILD" --output-on-failure
```

Linux 程序位于 `$CONSUMER_BUILD/bin/CaliburnConsumerApp`，macOS 位于 `$CONSUMER_BUILD/bin/CaliburnConsumerApp.app`。测试从构建目录运行，验证 Shell 约定定位、typed 初始注入、ViewHost 页面装配、NOTIFY 更新、框架默认确认资源、接受/取消和 `Screen.tryClose` 关闭窗口。离屏测试不替代人工 GUI 验收。

## 接入自己的应用

将框架固定到明确 tag 或提交，以源码检出或子模块方式放入应用依赖目录。框架更新后重新配置并重新编译，不依赖移动分支作为发布版本。

```cmake
set(CALIBURN_BUILD_EXAMPLE OFF CACHE BOOL "" FORCE)
set(CALIBURN_BUILD_TESTS OFF CACHE BOOL "" FORCE)
add_subdirectory(third_party/caliburn-micro-qt)

qt_add_qml_module(MyApplicationModule
    STATIC
    URI MyApplication
    VERSION 1.0
    RESOURCE_PREFIX /qt/qml
    DEPENDENCIES TARGET CaliburnMicroQt
    # SOURCES 与 QML_FILES 按自己的应用声明。
)
target_link_libraries(MyApplicationModule PUBLIC Caliburn::MicroQt)
```

框架的两个开关默认随是否作为顶层工程构建而变化；显式关闭可避免复用 CMake 缓存时意外开启示例与测试。仅框架接入不进入示例依赖的 FetchContent，也不下载 Boost.DI 或 spdlog。消费应用需要自己启用 C++17 和 Qt 的项目设置。

公开 C++ 头文件统一使用 `#include <CaliburnMicroQt/类型名.h>`；不要加入框架 `src` 或示例目录到 include path。QML 使用 `import Caliburn.Micro.Qt 1.0`。通用生命周期、Conductor、ViewHost 和窗口服务由框架提供，业务模型、服务、主题与装配容器由应用定义。

## 静态插件与约定定位

1. 使用 `qt_add_qml_module` 为应用模块生成注册、qmldir 和资源。可统一设置 `QT_QML_OUTPUT_DIRECTORY`，供模块工具和 Qt Creator 查找类型信息。
2. 为应用视图设置资源别名。例如 `qml/views/ShellView.qml` 的别名为 `views/ShellView.qml`，则资源 URL 为 `qrc:/qt/qml/MyApplication/views/ShellView.qml`。
3. Bootstrapper 注册根工厂并添加 `ViewLocator::addSearchRoot({QUrl("qrc:/qt/qml/MyApplication/")})`。业务 View 声明 `required property ShellViewModel viewModel`，根窗口与页面使用不同模型类型。
4. 约定定位在运行时按 URL 加载资源，静态链接器必须保留对应插件。独立消费工程显式链接 `CaliburnConsumerModuleplugin`，并在入口使用 `Q_IMPORT_QML_PLUGIN(CaliburnConsumerModulePlugin)` 和 `Q_IMPORT_QML_PLUGIN(CaliburnMicroQtPlugin)`；框架插件依赖通过 Qt 的模块依赖传递。普通可执行目标配合显式导入可避免重复扫描；使用 `qt_add_executable` 的应用应核对 Qt 自动导入结果，避免再次重复链接同一个插件。
5. 同时链接应用 backing library，以取得它的公开 include 和使用要求；插件的链接关系不等于公开头文件传播。完整可运行写法以独立消费工程的 CMake 为准。

框架确认 View 已内嵌在静态模块资源中；窗口服务通过框架默认搜索根定位，不需要复制 QML 文件或由业务登记默认映射。部署时仍需要平台对应的 Qt 动态库、QML 插件及图形后端；本轮验证依赖已安装的 Qt kit，未制作分发包。

## 麒麟更新与 Qt Creator 验证

麒麟已有的环境脚本为 `~/Qt/qt6-8.3-env.sh`，Qt Creator 14 入口为 `~/Qt/qtcreator-14.0.2`。系统 Qt 5 Creator 与 Qt 6 Creator 配置分别维护。

```bash
cd ~/Githubs/caliburn-micro-qt
git pull --ff-only
source ~/Qt/qt6-8.3-env.sh
cmake --preset debug
cmake --build --preset debug --parallel 4
ctest --preset debug
cmake --build --preset debug --target all_qmllint
```

在 Qt Creator 14 打开仓库根 `CMakeLists.txt`，选择 `Desktop Qt 6.8.3 Kylin x86_64`、Debug 和 `CaliburnExampleApp`。更新后重新运行 CMake，再按 Ctrl+R。手动核对计数/键盘、详情导航及退出确认、重置确认、取消保持状态、根窗口退出守卫与日志显示；结果由人工确认后补入第八批验收记录。

如果 IDE 同时自动重新配置，命令行验证宜使用另一个构建目录，避免两次 CMake 同时写入同一目录。无需删除个人 `.user`、重新注册 Kit 或修改系统 Qt。
