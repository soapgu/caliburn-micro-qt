# 窗口管理与 Conductor 接口化迁移

窗口、弹窗、根工厂和 Conductor 成员统一允许 QObject，Screen 继续提供完整生命周期与 tryClose 便利行为。此变更不保留旧签名适配层；消费工程需同步迁移并重新编译。

## 公开类型

```cpp
#include <CaliburnMicroQt/DialogResult.h>

bool showWindow(const QVariant &viewModel);
QFuture<DialogResult> showDialogAsync(std::unique_ptr<QObject> model,
                                    QObject *requester);
QObject *currentDialog() const;

// IParent / IConductor / ICloseStrategy 与非模板扩展点：
QList<QObject *> getChildren() const;
void activateItem(QObject *item);
void deactivateItem(QObject *item, bool close);
```

activeItem 的 QML 属性及 activationProcessed 的对象参数改为 QObject*；items 仍为只读 QVariantList。自定义关闭策略、ensureItem、prepareCloseItem、determineNextItemToActivate、onActivationProcessed 等覆盖签名同步修改。基类类型、公开属性、虚接口和信号均改变 C++ ABI。

Conductor<T> 和 Conductor<T>::Collection::OneActive 默认 T = QObject，类型化入口仍返回 T* / QList<T*>。基类、IConductor 和 QML 属性赋值同样检查模板的实际类型，不能绕过类型限制。普通窗口仍传 QVariant::fromValue(具体类型指针)，保留 typed QML 初始属性注入；QML 可继续声明具体业务类型或使用 QtObject 接收通用模型。

根工厂允许 QObject 派生类型并由 Bootstrapper 独占根对象。仅在存在对应接口时执行根生命周期；退出顺序及 onExit 可观察寿命保持不变。

## 能力与通知

| 接口 | 接入行为 | 缺少接口时 |
| --- | --- | --- |
| IActivate | 调用 activate，接管时检查 isActive | 跳过激活及活动状态检查 |
| IDeactivate | 调用 deactivate，订阅尝试/完成通知 | 跳过停用 |
| IGuardClose | 关闭前询问许可 | 默认允许 |
| IChild | 维护与检查逻辑 Parent | 仅维护 QObject 所有权 |

IDeactivate/2.0 新增以下纯虚方法，自定义实现必须补齐：

```cpp
QMetaObject::Connection subscribeAttemptingDeactivation(
    QObject *context, DeactivationCallback callback) override;
QMetaObject::Connection subscribeDeactivated(
    QObject *context, DeactivationCallback callback) override;
```

DeactivationCallback 为 std::function<void(bool)>。实现使用带 context 的 QObject::connect 连接自身信号，返回有效连接；接收者销毁后自动断开，也允许显式 disconnect。信号名称不限，不使用名称反射。对象寿命、方法、通知及回调均遵循主线程约定。

尝试通知先于生命周期执行，完成通知仅在正常完成后发送。close=true 的完成通知反向关窗；普通停用不关窗。窗口服务和根退出按尝试通知避免重试失败关闭。Screen 复用已有 attemptingDeactivation / deactivated 信号。

IParent IID 升为 Caliburn.Micro.Qt.IParent/2.0，IConductor 升为 Caliburn.Micro.Qt.IConductor/3.0，IDeactivate 升为 Caliburn.Micro.Qt.IDeactivate/2.0。QML URI 保持 Caliburn.Micro.Qt 1.0。

## 关闭请求与所有权

不新增 ICloseRequestSource 或 IClose。Screen.tryClose(result) 仍先委托 Parent Conductor，否则发送 closeRequested；窗口层仅在对象确为 Screen 时连接该信号。currentDialog 返回 QObject*，需要 Screen 方法的代码须显式 qobject_cast，或保留原始具体模型的 QPointer。

普通 QObject 可通过窗口标题栏或 Escape 关闭；实现 IDeactivate 后还可通过关闭完成通知反向关窗。普通对象主动提交 true/false 弹窗结果不在本批；窗口操作和强制清理返回空结果。直接完成关闭生命周期不再询问守卫，沿用 Screen 的既有行为。

普通窗口借用模型；弹窗按值消费 unique_ptr；Conductor 通过 unique_ptr 接管并设置 QObject 父对象与 CppOwnership。逻辑 Parent 仅在实现 IChild 时维护。关闭、移出成员不自动删除 Conductor 接管的对象，意外销毁会清理活动项及集合记录。

本次不改变创建/激活时序、关闭策略、单窗口/单弹窗限制、焦点恢复或强制退出清理，不引入 View 关联、View 缓存、context 或 Action。
