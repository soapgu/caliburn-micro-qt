# 框架与 example 同步迭代的实现计划

> 状态：实施规划，以下六批功能均未实现。本轮只完善文档，不创建源码、构建骨架或占位类型；文中的接口和验收场景不代表已有实现或通过结果。

## 1. 迭代方式

每次迭代完成一批可运行、可验证的功能，同时交付**框架能力、example 演示、必要测试和验收记录**。框架新增能力应在同批 example 中使用，验收通过后再进入下一批，不先实现整套框架再补示例。

技术基线、模块目标与依赖方向沿用 [模块与项目结构](模块与项目结构.md)：Qt 6.8.3、C++17，`CaliburnMicroQt` / `Caliburn::MicroQt`、`CaliburnExampleModule` 和 `CaliburnExampleApp`。两个模块采用静态库，QML URI 保持 `Caliburn.Micro.Qt 1.0` 与 `CaliburnExample 1.0`；批次编号和模块版本分别记录，URI 的 1.0 不表示六批能力都已实现。

example 默认采用显式构造注入，框架不依赖 DI 库。只创建当前批次需要的文件，公共预设不包含个人 Qt 路径。

从第一批起，ShellViewModel / ShellView.qml 始终作为应用入口。Shell 是项目命名约定，不表示第一批就需要 Conductor：先完成一个页面的绑定，再逐批增加生命周期、子页面和导航。

## 2. 第一版：单页面按钮与文字绑定

### 本批交付

| 单元 | 待实现内容 |
| --- | --- |
| 框架模块 | `ViewModelBase` 及其 protected 类型化 `setAndNotify`、支持无参数操作的 `ActionBinding`、`ActionButton`。 |
| 用户模块 | `ShellViewModel : ViewModelBase` 和唯一页面 `ShellView.qml`。 |
| 启动程序 | 创建一个根 Shell VM，设置 C++ 所有权，通过引擎初始属性注入 viewModel，直接加载根窗口资源。 |
| 工程 | 两个静态模块、独立启动程序、必要测试入口；完成跨模块类型注册、静态插件链接与资源装配。 |

第一版的 ShellView 根对象是 ApplicationWindow，声明 `required property ShellViewModel viewModel`。启动程序直接加载 `qrc:/qt/qml/CaliburnExample/views/ShellView.qml`，创建失败时诊断并非零退出。根 VM 无 QObject 父对象，由 C++ RAII 持有；退出时先销毁引擎和 View，再销毁 VM。

本批不引入 Screen、Conductor、ViewRegistry、ViewHost、快捷键、业务服务或弹窗，也不为这些后续能力创建占位实现。

### 页面与 VM 契约

页面采用点击计数示例，只保存一份 C++ 计数状态，初始为 0，上限为 5。

| 页面元素或 VM 成员 | 目标绑定与行为 |
| --- | --- |
| `count` | 只读 int 属性，实际变化发 `countChanged`。 |
| `message` | 根据 count 计算的只读文字属性，使用 countChanged 通知；初始为“已点击 0 次”。 |
| `incrementText` | 常量文字属性，值为“增加”，绑定增加按钮的 text。 |
| 增加按钮 | ActionButton 的 target 指向 Shell VM，action 为 `increment`，arguments 为空。 |
| 重置按钮 | text 为“重置”，target 指向 Shell VM，action 为 `reset`，arguments 为空。 |
| `canIncrement` | 可读 bool 属性，count < 5 时成立，结果变化时发对应 NOTIFY。 |
| `canReset` | 可读 bool 属性，count > 0 时成立，结果变化时发对应 NOTIFY。 |
| `increment()` | 公开无参数 Q_INVOKABLE void 方法；条件成立时增加 1。 |
| `reset()` | 公开无参数 Q_INVOKABLE void 方法；条件成立时归零。 |

文字由 QML 属性绑定读取 VM，按钮通过框架 ActionBinding 调用 VM。QML 不维护第二份计数、不直接写 count，也不自行计算业务守卫。VM 方法自身再次检查条件，不依赖按钮禁用来保证上限。

Shell VM 更新 count 使用 `setAndNotify(m_count, value, &ShellViewModel::countChanged)`，message 复用 countChanged；canIncrement/canReset 对比更新前后的 bool 结果后分别通知。基类仅增加构造/析构及此辅助函数，不增加 displayName、业务属性、状态、信号或字符串通知；完整成员和示例见 [ViewModelBase](ViewModelBase.md)。

第一批 ActionBinding 保留 target、action、arguments、enabled 和 execute 的目标接口，但 arguments 只接受空列表；非空参数、重载、非 void 返回、缺少方法或 bool 守卫/NOTIFY 均诊断并禁用。目标更新时断开旧连接，目标销毁后禁用；execute 重新读取守卫，在同一 GUI 线程调用。完整目标契约见 [ActionBinding](ActionBinding.md)，单个 int 参数在第二批加入。

### 实施顺序与验收

1. 建立两个静态模块、启动目标和 ViewModelBase（含类型化通知辅助），确认用户模块的 ShellViewModel 可在 QML 中跨模块识别并接收初始属性。
2. 同步实现 ActionBinding、Shell VM 操作与守卫，接入必要 C++ 测试。
3. 实现 ActionButton 与 ShellView 的文字/按钮绑定，完成资源和插件装配。
4. 执行配置、构建、相关测试并运行 example；以上步骤合为一批，不以中间骨架代替第一版交付。

自动测试覆盖 Shell 的跨模块 VM 类型、计数与文案通知、守卫边界、直接调用 VM 的条件检查、execute 执行前复核、非法方法/参数配置、目标替换和销毁。QML 集成检查 ShellView 的初始 typed Shell VM 注入、文字更新和按钮 enabled 状态。

基类辅助测试还须覆盖同值不赋值/不通知、更新返回 true、赋值先于通知、空信号及不兼容 Owner 诊断且不修改字段。保留不可由 QML 创建和 C++ 所有权验证，不把基类字符串反射通知或生命周期作为第一批功能。

真实界面验收：启动显示“已点击 0 次”，增加可用、重置禁用；点击增加后文字依次更新；到 5 时增加禁用；重置后回到 0 且可用状态恢复。仅从构建产物启动也能找到两个模块及页面资源。

## 3. 后续迭代批次

| 批次 | 同批框架功能 | 同批 example 与主要验收 |
| --- | --- | --- |
| 1．单页面绑定 | ViewModelBase 与类型化 setAndNotify、无参数 ActionBinding、ActionButton。 | ShellViewModel 继承 ViewModelBase，ShellView 根窗口展示计数、文字通知和守卫禁用，应用可构建启动。 |
| 2．参数与键盘 | ActionBinding 增加单个 int 参数；KeyActionBinding。 | Shell 同页增加 `add(int)` 及“加 2”按钮，快捷键调用同一操作；验证参数形态、业务范围、自动重复过滤及按钮先消费按键。 |
| 3．生命周期与视图装配 | ScreenViewModel、ViewRegistry、ViewHost。 | Shell 改为 Screen，新增 Home Screen 与 Item 页面承接计数；Shell 根窗口的 ViewHost 绑定 `viewModel.home`。验证初始化/激活幂等、同类型 VM 替换、空模型、目标销毁和加载失败。 |
| 4．页面组合与导航 | ConductorViewModel，子项接管、活动项切换与非活动项移除。 | Shell 演进为 Conductor，宿主绑定 `viewModel.activeItem`；加入详情页和业务服务，Home 常驻，Detail 按需创建，返回后延迟释放。验证共享服务身份、唯一活动项、所有权交接和退出回收。 |
| 5．异步确认 | ConfirmationRequest、确认 VM/View、IDialogService、DialogService、DialogHost。 | Shell 根窗口承载 DialogHost，Home 重置及 Detail 离开加入确认；验证接受、取消、忙状态、请求者失效、一次异步结果、模态输入隔离与焦点恢复。 |
| 6．下游接入与平台验证 | 完善框架独立构建、静态模块接入及相关文档。 | 验证持续使用的 Shell 入口及独立最小消费工程；消费工程只引用框架。验证 macOS arm64 与麒麟 x86_64 的构建、资源加载及真实 GUI，更新 qt-snake-lab 接入概要。 |

第二批的 `add(int)` 保留 0～5 的计数范围，example 使用正增量；不接受的业务输入由 VM 拒绝且不改变计数，框架只检查参数形态。已有 increment/reset 行为继续保留。

第三批保持 ShellViewModel / ShellView 根入口，将 ShellViewModel 的基类改为 ScreenViewModel，新增 HomeViewModel : ScreenViewModel 和根对象为 Item 的 HomeView.qml。计数存储、文案、increment/reset/add 操作及所有守卫整体移入 Home，Shell 不保留第二份状态或操作实现，只提供类型化 `home` 页面入口；ShellView 的 ViewHost 绑定 `viewModel.home`，仍只有一个计数页面。

本批 Home 由 Shell 的 QObject 父所有权管理，不与 unique_ptr 同时负责删除；应用装配层显式安排 Shell 和 Home 的初始化与激活，不提前实现 Conductor。加载前登记 Shell → views/ShellView.qml 和 Home → views/HomeView.qml 两个不同映射，C++ 根入口和 QML ViewHost 使用同一份配置。验收覆盖两个对象的生命周期和身份、Home 的单份状态以及宿主替换/清空。

第五批才登记框架 ConfirmAction VM/View 映射；第一、二批直接加载固定根窗口地址，不要求尚未实现的注册表或生命周期 API。

第四批保持 Shell 根入口，将其基类改为 ConductorViewModel；ShellView 的宿主从 `viewModel.home` 改为 `viewModel.activeItem`。子项改按 Conductor 接管契约创建：应用提供无既有父对象的 Home/Detail 候选项，经 addItem 接管后由 QObject 父树管理，不能把第三批已带 parent 的对象再次交给 addItem。Home 常驻，Detail 按需创建，返回后停用、切换、移除并延迟释放；初始化、激活和停用改由 Conductor 管理。

本批引入业务服务后，计数事实由该服务保存，Home/Detail VM 改为展示投影，通过构造注入借用同一个实例；服务寿命长于 VM。导航和界面卸载不重置计数，不复制一份服务状态。该演进仍须回归第一批的文字、操作和守卫行为。第五批确认操作分别留在 Home 和 Detail，Shell 根窗口只承载 DialogHost，不接管它们的业务操作。

## 4. 每批完成标准与记录

- 每批必须同时具备框架实现、example 使用路径、必要测试和验收记录。只有本机配置、构建、相关自动测试及实际 example 操作全部通过，才将该批标为完成。
- 后续批次增加对应功能测试并回归已有操作，不为未实现能力提前登记测试通过状态；离屏测试不替代真实焦点、模态与窗口交互验收。
- README 汇总当前完成批次、已实现能力、验证结果、下一批和待验证平台；实现计划记录各批状态及实际验收证据，不把文档完善标为功能完成。
- 每批记录环境、验证方式、结果与未验证项；第六批前未验证的麒麟状态保留“待验证”，不能用本机通过替代。
- 发布批次和 QML URI 版本分开记录；源码只包含当前已交付功能，不用空类型或空方法冒充后续接口。
