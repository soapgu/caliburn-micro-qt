# 日志接入

6A 使用 Qt 原生分类日志，由 example 接管输出并转交 spdlog。6B 为框架接入分类诊断与关键流程日志。框架没有 `ILog/LogManager`，不依赖 spdlog，也不安装进程级消息处理器。项目维护的日志与异常诊断统一使用英文；界面文案继续使用中文，Qt/QML 和第三方组件自身诊断保留上游原文。

## 分类、级别与源码定位

example 共享 `exampleLog`，分类名为 `caliburn.example`：

```cpp
#include <ExampleLog.h>

void CounterService::add(int delta)
{
    qCDebug(exampleLog) << "Counter increment requested; delta:" << delta;
    // 业务逻辑……
    qCInfo(exampleLog) << "Counter updated";
}
```

Debug 构建默认输出 Debug 及以上；Release、RelWithDebInfo、MinSizeRel 默认输出 Info 及以上。默认阈值由分类声明设置，Qt 内部分类沿用原有默认值。框架分类采用 `caliburn.microqt.*`，默认阈值与 example 一致。

分类用于过滤；函数和文件行号用于定位。默认格式包含时间、Qt 原始级别、线程、分类、函数、文件行号和正文。项目编译统一定义 `QT_MESSAGELOGCONTEXT`，Release 也保留调用位置。成员函数包含所属类名；公共辅助函数只能标识辅助函数位置，具体 VM 实例需要在正文中写入类型或对象标识。

```text
[2026-10-11 12:00:00.000] [info] [tid=123] [caliburn.example] CounterService::add [CounterService.cpp:14] Counter incremented; delta: 1 current value: 1
```

使用 Qt 原生环境变量覆盖默认过滤与格式，例如：

```sh
export QT_LOGGING_RULES='caliburn.example.debug=true'
export QT_MESSAGE_PATTERN='[%{type}] [%{category}] %{function} [%{file}:%{line}] %{message}'
```

`QT_LOGGING_RULES='caliburn.example.debug=false'` 可在开发构建关闭调试日志。过滤发生在输出处理器之前；被过滤的消息不会写入控制台或文件。不要定义 `QT_NO_DEBUG_OUTPUT` 来代替运行时过滤，否则无法通过环境变量重新开启。

## 框架分类与级别

| 分类 | 记录范围 |
| --- | --- |
| `caliburn.microqt.core` | 基类通知契约诊断 |
| `caliburn.microqt.lifecycle` | Screen 初始化、激活、停用、关闭及逻辑 Parent |
| `caliburn.microqt.conductor` | 活动项切换、集合维护与关闭许可 |
| `caliburn.microqt.view` | 映射登记与查询、ViewHost 加载和装配 |
| `caliburn.microqt.window` | 普通窗口、弹窗、关闭桥接与焦点恢复 |
| `caliburn.microqt.bootstrapper` | 应用配置、启动、清理和最终退出码 |

关键过程与结果使用 Info；初始化、请求、重复调用、映射查询和资源维护使用 Debug。正常取消、守卫拒绝关闭使用 Info；无效契约和可恢复失败使用 Warning；启动或退出清理错误沿用 Critical。日志包含运行时类型与地址标识，例如 `HomeViewModel@0x1234`；地址仅用于本次进程内定位。视图记录 URL，弹窗结果区分 `accepted`、`rejected`、`cancelled`。

生命周期遵循 CM 3.2.0 的记录时机：`Activating`、`Deactivating` 在业务钩子之前记录，表示开始执行；`Closed` 在关闭钩子与停用通知正常返回后记录。钩子抛异常时不会出现 `Closed`。生命周期和导航异常继续按原契约传播，日志不增加重试或回滚。

ViewHost 通过 `ViewHostState.reportLoadStarted/reportLoadSucceeded/reportLoadFailed` 进入 C++ 分类出口。`errorString` 为英文技术诊断；QML 引擎自身可能另外输出详细加载原因。

```sh
# Release 中开启全部框架细节
export QT_LOGGING_RULES='caliburn.microqt.*.debug=true'
# 只关闭视图分类的正常流程信息，保留 Warning/Critical
export QT_LOGGING_RULES='caliburn.microqt.view.debug=false;caliburn.microqt.view.info=false'
```

CM 3.2.0 的 `ILog` 只有 Info/Warn/Error，`LogManager` 默认空实现；这里对齐关键生命周期与视图诊断语义，保留 Qt 分类过滤和 6A 的默认输出。Conductor、窗口与启动扩展日志服务于 Qt 实现的排障，不增加 CM 的约定绑定或视图缓存行为。依据：[Screen](https://github.com/Caliburn-Micro/Caliburn.Micro/blob/3.2.0/src/Caliburn.Micro/Screen.cs)、[ViewLocator](https://github.com/Caliburn-Micro/Caliburn.Micro/blob/3.2.0/src/Caliburn.Micro.Platform/ViewLocator.cs)、[ViewModelBinder](https://github.com/Caliburn-Micro/Caliburn.Micro/blob/3.2.0/src/Caliburn.Micro.Platform/ViewModelBinder.cs)、[ILog](https://github.com/Caliburn-Micro/Caliburn.Micro/blob/3.2.0/src/Caliburn.Micro/ILog.cs)、[LogManager](https://github.com/Caliburn-Micro/Caliburn.Micro/blob/3.2.0/src/Caliburn.Micro/LogManager.cs)。

## example 输出配置

启动目标链接独立的 `CaliburnExampleLogging`；业务模块只依赖 Qt 分类声明，不链接 spdlog。日志支持目标链接 FetchContent 提供的 `spdlog::spdlog` 静态库，使用其自带 fmt。只构建框架时关闭 `CALIBURN_BUILD_EXAMPLE` 和 `CALIBURN_BUILD_TESTS`，不获取 spdlog 或 Boost.DI。

## 依赖下载与离线构建

`cmake/ExampleDependencies.cmake` 集中管理 spdlog v1.17.0 和 Boost.Ext.DI v1.3.2，spdlog 下载官方版本归档，Boost.DI 下载官方版本的单头文件，均校验 SHA-256。Boost.DI 在使用本地源码覆盖时仍校验头文件，确保内容与原仓库副本一致。关闭第三方示例、测试、基准和安装规则，项目配置时即可使用目标，不执行系统安装。

Boost.DI 不下载完整仓库或执行上游 CMake，由项目提供 INTERFACE 目标；`#include <boost/di.hpp>` 和私有链接方式不变。首次配置需要网络，源码及产物默认保存在当前构建目录的 `_deps`；同一构建目录后续复用缓存。Qt Creator 只需现有 Qt Kit，无需 Homebrew、apt 或 `spdlog_DIR`。迁移旧构建时移除个人预设及 IDE 中的旧 `spdlog_DIR`，重新配置项目。

已成功下载两个依赖的构建目录可禁止后续网络访问：

```sh
cmake --preset debug -DFETCHCONTENT_FULLY_DISCONNECTED=ON
cmake --build --preset debug
```

全新离线构建需先准备指定版本文件：解压 spdlog 归档，并将官方 Boost.DI 单头文件保存为一个独立目录中的 `di.hpp`。通过标准变量提供路径；这些路径只放在个人预设或命令行：

```sh
cmake --preset debug \
  -DFETCHCONTENT_SOURCE_DIR_SPDLOG=/path/to/spdlog-1.17.0 \
  -DFETCHCONTENT_SOURCE_DIR_BOOST_DI=/path/to/boost-di-header
```

spdlog 源码目录覆盖不会校验下载归档，使用者应预先校验归档 SHA-256；Boost.DI 头文件校验仍会执行。下载或校验失败会终止配置，不自动切换系统包或其他版本。删除构建目录后需要重新下载，或再次提供本地源码。详见 [FetchContent 官方文档](https://cmake.org/cmake/help/v3.21/module/FetchContent.html)。

## 输出与刷新

默认同步写入控制台和 `QStandardPaths::AppLocalDataLocation/logs/CaliburnExampleApp.log`。example 设置组织名 `CaliburnMicroQt` 和应用名 `CaliburnExampleApp`，启动日志打印实际路径。单文件上限 5 MiB，保留 3 个历史文件；跨启动追加，达到上限时轮转。macOS 可在 `~/Library/Application Support/CaliburnMicroQt/CaliburnExampleApp/logs/` 查找。

`LoggingOptions` 允许应用内部或测试指定文件路径、大小、历史文件数和控制台颜色模式；不是框架公共 API。目录或文件不可用时报告错误并降级为控制台，应用继续运行。运行时 sink 错误直接输出标准错误，不重新进入 Qt 或同一个 logger。

Qt Debug/Info/Warning/Critical/Fatal 对应 spdlog debug/info/warn/err/critical。正文由 `qFormatLogMessage` 格式化，spdlog 只原样输出，保留 Qt 的原始级别。spdlog 不再增加级别过滤。Warning 及以上立即刷新，普通消息在正常退出时刷新；Fatal 在 Qt 终止前同步刷新。不保证进程被强制杀死或掉电时保留尚未刷新的普通消息。

## 控制台等级颜色

示例将所有级别写入同一个 `stderr`，按等级对整条日志着色：Debug 深灰色（macOS/Linux 使用 RGB `128,128,128`，Windows 使用不带高亮的普通灰色前景）、Info 绿色、Warning 加粗黄色、Critical 红色、Fatal 加粗红色。Debug 使用 ANSI `38;2;128;128;128` 指定 RGB 灰色，以兼容忽略 ANSI `90` 色码的 Qt Creator 20.0.1；其余等级的实际色值由终端或 IDE 的调色板决定，文字级别标识仍保留。每条日志着色结束后恢复默认样式，避免影响后续 IDE 提示。

控制台与文件分别配置 spdlog 格式；着色只发生在控制台 sink，文件不添加 ANSI 转义码。Qt 分类过滤、源码位置和 `QT_MESSAGE_PATTERN` 继续有效。不应通过在 `QT_MESSAGE_PATTERN` 中手工加入颜色码实现着色，否则这些内容也会进入文件。

`CMQT_LOG_COLOR` 在初始化时读取，支持以下值（忽略首尾空白及大小写）：

| 值 | 行为 |
| --- | --- |
| `auto` | 默认；由 spdlog 检测终端能力。macOS/Linux 的管道或重定向输出不添加颜色码。 |
| `always` | 强制启用颜色。macOS/Linux 可用于支持 ANSI 的 IDE 输出面板。 |
| `never` | 禁用颜色，方便脚本处理或排障。 |

应用内部可设置 `LoggingOptions::consoleColor` 为 `ConsoleColorMode::Automatic/Always/Never`，默认 `Automatic`。有效且非空的环境变量优先于此设置；无效值输出一次英文提示并使用内部设置。颜色配置不修改日志过滤阈值。

Qt Creator 的应用程序输出通常通过管道捕获，`auto` 可能不着色，标准错误仍显示 IDE 的默认红色。要开启等级颜色，在 **项目 → 运行设置 → 运行环境** 中添加：

```text
CMQT_LOG_COLOR=always
```

该设置属于本机运行环境，不必提交个人 IDE 配置。普通终端可使用 `CMQT_LOG_COLOR=always <程序路径>` 强制着色，或使用 `CMQT_LOG_COLOR=never <程序路径> 2>console.log` 保存无颜色的控制台输出。CI 建议使用 `auto` 或 `never`，无需强制着色。

Windows 使用 spdlog 原生控制台着色，需要实际 Windows 控制台；`always` 不保证通过管道捕获的 IDE 输出面板有颜色。Windows 和麒麟上的实际显示效果需要分别验收。日志输出组件自身的降级提示，以及组件接管前或恢复旧处理器后的消息，沿用原处理路径，不受本组件等级颜色控制。

## 生命周期与下游复用

`main` 先声明 `LoggingRuntime`，再构造应用；设置应用信息后初始化日志。这样出口覆盖 Bootstrapper、资源清理和应用析构。应用构造期间的早期日志仍由 Qt 原处理器输出。

Qt 全进程只有一个消息处理器。日志运行对象保存旧处理器，结束时恢复；转发成功时不重复调用旧处理器。运行期间应用不要自行替换处理器，也不要创建第二个日志运行对象。Qt 调用可能来自多个线程，处理器使用共享状态快照及线程安全 sink；应用仍应在退出前回收业务线程。

下游应用可复用 example 的 `LoggingRuntime`，也可以提供自己的输出处理器；框架无需修改。桥接方向保持 `Qt → spdlog → 控制台/文件`，不要配置重新调用 Qt 日志的 sink。此版本不增加异步队列、日志面板或框架日志抽象。

参考：[Qt 分类日志](https://doc.qt.io/qt-6.8/qloggingcategory.html)、[Qt 消息处理器与格式](https://doc.qt.io/qt-6.8/qtlogging.html)、[spdlog 输出示例](https://github.com/gabime/spdlog#usage-samples)。
