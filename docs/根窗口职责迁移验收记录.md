## 实现与耦合边界

- IWindowManager 新增 `bool showWindow(const QVariant &viewModel)`。DisplayRootView 只委托显示并记录成功状态，不再创建引擎、加载 QML 或持有 WindowConductor。
- WindowManager 的私有 ManagedWindow 持有 QQmlApplicationEngine、窗口借用指针及桥接；普通窗口 VM 由调用方持有。类型化 QVariant 原样注入 QML，Screen 指针只用于映射、守卫和生命周期。
- 正常关窗后的 VM 停用由 WindowManager 执行，已尝试的关闭不重试。异常捕获后发出 windowCleanupFailed，由 Bootstrapper 保留失败退出码，无需窗口层引用 Bootstrapper 或业务类型。
- Bootstrapper 保留根工厂、根 VM unique_ptr、应用事件循环、OnExit 及失败/强制退出时的根生命周期兜底。普通窗口服务不强持有根 VM，不与业务持有的服务 shared_ptr 形成所有权环。
- prepareForShutdown 停用桥接并结束弹窗；成功展示后的根 View 和 VM 在 OnExit 中保持存活。事件循环返回后显式 releaseWindows，再删除根 VM；即使业务仍持有服务，窗口资源也及时释放。
- 显示失败立即释放部分资源并关闭已激活 VM，允许服务再次显示；激活异常清理后原样传播。服务已关联其他窗口时在激活候选前拒绝，hostFailure 的根关闭通知预期因此由一次变为零次。
- 独立服务强制释放或析构时，先释放 View/引擎，再关闭尚未尝试关闭的借用 VM，不删除 VM。外部登记的窗口/引擎仍归调用方；VM/窗口意外销毁时在析构栈退出后清理，续接绑定旧桥接，不能影响新窗口。

普通窗口打开不占用弹窗 busy/currentDialog；普通窗口与弹窗共用 WindowConductor 守卫桥接，分别保留借用 VM 和接管弹窗 VM 的收尾策略。服务支持一个自建普通窗口与一个当前弹窗，多普通窗口管理未扩展。

CM 3.2.0 对齐的是 Bootstrapper → IWindowManager.ShowWindow 的委托及窗口层职责。本次保持先激活 VM 再加载 View，普通 View 仍须是 QQuickWindow。创建/绑定/激活顺序、普通 Item 窗口包装和通用 CreateWindow/EnsureWindow 作为独立变更处理；没有新增通用 IoC、WPF NavigationWindow、Popup 或同步 ShowDialog。
