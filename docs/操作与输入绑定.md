# 操作与输入绑定：显式条件与方法调用

> 状态：第一批按钮使用手写 QML 属性绑定和事件处理器；1.0 不提供动作自动装配、统一执行或输入适配组件。参数与键盘演示属于第二批规划，尚未实现。当前验证见 [第一批验收记录](第一批验收记录.md)。

## 1. 按钮直接绑定 VM

业务 View 声明明确类型的 required viewModel，创建前由应用注入。属性、可用状态和方法由业务 VM 提供，按钮写明要读取的条件与调用的方法：

```qml
import QtQuick
import QtQuick.Controls
import CaliburnExample 1.0

Item {
    id: root
    required property ShellViewModel viewModel

    Button {
        objectName: "increment"
        text: root.viewModel.incrementText
        enabled: root.viewModel.canIncrement
        onClicked: root.viewModel.increment()
    }

    Button {
        objectName: "reset"
        text: "重置"
        enabled: root.viewModel.canReset
        onClicked: root.viewModel.reset()
    }
}
```

objectName 仅用于对象标识与测试；改名不改变上述方法调用。canIncrement/canReset 是示例业务命名，不是框架自动推导的守卫。普通 Button、ToolButton 和样式派生控件使用相同的 Qt 属性与信号。

当前实际根窗口为 ApplicationWindow，完整代码见 [ShellView.qml](../examples/minimal/CaliburnExample/qml/views/ShellView.qml)。上面的 Item 片段只展示交互绑定。

## 2. 可用状态通过属性通知刷新

Shell VM 用 Q_PROPERTY 暴露可读 bool，并为可变结果声明 NOTIFY；canIncrement 根据 count < 5 计算，canReset 根据 count > 0 计算。结果改变后 VM 发出通知，QML 重新读取表达式并更新 enabled。

```text
VM 更新计数
    → 通知文字与可用状态属性
    → QML 属性表达式重新求值
    → 标签文字、按钮 enabled 更新
```

这由 Qt 原生属性绑定处理，不扫描视觉树、不轮询、不需要额外接线对象。恒定状态可以由业务 VM 使用 CONSTANT 属性表达；View 也可以显式组合多个展示条件。

没有可用条件的按钮可以保留 Qt 默认 enabled，或绑定应用提供的其他条件。框架不根据方法名寻找 canXxx，也不规定方法必须返回 void、无参数或不重载。

动态属性的通知仍由 VM 明确维护。基类 setAndNotify 只更新字段并发指定信号，不自动推导属性依赖；见 [ViewModelBase](ViewModelBase.md)。

## 3. 方法自身保证业务规则

用户点击按钮后 onClicked 直接调用公开的 Q_INVOKABLE 方法或槽。按钮禁用是展示状态，不能代替业务规则检查：increment() 自身仍判断上限，reset() 自身判断是否需要归零，从 C++ 直接调用也不能越过范围。

```text
用户点击
    → QML onClicked
    → VM 方法检查条件
    → 执行业务操作并发送属性通知
```

框架没有独立的执行前守卫复核层。业务条件及参数范围由 VM 和业务用例分别负责；点击处理器不要复制计数状态或直接修改业务字段。导航和确认 View 同样显式调用所属 VM 的方法。

## 4. 显式目标与对象替换

调用其他 VM 时在表达式中明确引用，不使用父链、窗口或方法名查找默认目标。下面的设计片段假定所属 View 已导入 ShellViewModel 类型：

```qml
property ShellViewModel otherViewModel: null

Button {
    text: "重置其他计数"
    enabled: root.otherViewModel !== null && root.otherViewModel.canReset
    onClicked: {
        if (root.otherViewModel)
            root.otherViewModel.reset()
    }
}
```

可空目标显式检查 null。替换 View 的 viewModel 或 otherViewModel 后，属性表达式跟随新对象；事件处理器执行时读取当前属性，不保存旧目标。不同 View 各自声明要引用的对象；不存在隐式动作作用域继承。

应用持有 VM，View 只借用。正常退出先销毁引擎与 View，再销毁 VM 树；动态页面先卸载旧 View，再释放其 VM。QML 绑定与事件处理器随 View 释放，不需要独立动作绑定对象。完整装配与所有权约定见 [ViewHost](ViewHost.md)。

## 5. 参数与键盘演示（第二批规划）

第二批保留 Shell 同页的 add(int)、参数按钮与快捷键演示，不增加框架输入组件。按钮处理器直接调用 root.viewModel.add(2)，不建立参数列表或反射调用路径；VM 验证正增量与 0～5 的业务范围。

键盘使用 Qt 原生 Keys 事件，在控件已有处理之后响应（Keys.AfterItem），显式选择按键并过滤自动重复。满足条件并处理事件后设置 event.accepted；无法处理时留给后续接收者。快捷键调用同一个 VM 方法，不另存业务状态。

焦点、事件消费顺序及自动重复属于 View；业务输入是否合法属于 VM。第二批才实现并测试这些例子，第一批没有快捷键。
