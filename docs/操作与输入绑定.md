# 操作与输入绑定：显式条件与方法调用

> 状态：第一批按钮使用手写 QML 属性绑定和事件处理器；1.0 不提供动作自动装配、统一执行或输入适配组件。第二批参数与键盘演示已实现，macOS arm64 / Qt 6.8.3 验收通过；第三批已将全部计数交互迁入 Home，装配与验收状态见 [第三批验收记录](第三批验收记录.md)。原始验证见 [第一批验收记录](第一批验收记录.md) 与 [第二批验收记录](第二批验收记录.md)。

## 1. 按钮直接绑定 VM

业务 View 声明明确类型的 required viewModel，创建前由应用注入。属性、可用状态和方法由业务 VM 提供，按钮写明要读取的条件与调用的方法：

```qml
import QtQuick
import QtQuick.Controls
import CaliburnExample 1.0

Item {
    id: root
    required property HomeViewModel viewModel

    Button {
        objectName: "increment"
        text: root.viewModel ? root.viewModel.incrementText : "增加"
        enabled: root.viewModel !== null && root.viewModel.canIncrement
        onClicked: { if (root.viewModel) root.viewModel.increment() }
    }

    Button {
        objectName: "reset"
        text: "重置"
        enabled: root.viewModel !== null && root.viewModel.canReset
        onClicked: { if (root.viewModel) root.viewModel.reset() }
    }
}
```

objectName 仅用于对象标识与测试；改名不改变上述方法调用。canIncrement/canReset 是示例业务命名，不是框架自动推导的守卫。普通 Button、ToolButton 和样式派生控件使用相同的 Qt 属性与信号。

当前计数页面的根对象为 FocusScope（Item 子类），由 Shell 的 ViewHost 承载。完整交互代码见 [HomeView.qml](../examples/minimal/CaliburnExample/qml/views/HomeView.qml)。上面的片段只展示交互绑定。

## 2. 可用状态通过属性通知刷新

Home VM 用 Q_PROPERTY 暴露可读 bool，并为可变结果声明 NOTIFY；canIncrement 根据 count < 5 计算，canReset 根据 count > 0 计算。结果改变后 VM 发出通知，QML 重新读取表达式并更新 enabled。

```text
VM 更新计数
    → 通知文字与可用状态属性
    → QML 属性表达式重新求值
    → 标签文字、按钮 enabled 更新
```

这由 Qt 原生属性绑定处理，不扫描视觉树、不轮询、不需要额外接线对象。恒定状态可以由业务 VM 使用 CONSTANT 属性表达；View 也可以显式组合多个展示条件。

没有可用条件的按钮可以保留 Qt 默认 enabled，或绑定应用提供的其他条件。框架不根据方法名寻找 canXxx，也不规定方法必须返回 void、无参数或不重载。

动态属性的通知仍由 VM 明确维护。基类 setAndNotify 只更新字段并发指定信号，不自动推导属性依赖；见 [ViewModelBase](ViewModelBase.md)。

## 3. 方法自身保证业务规则

用户点击按钮后 onClicked 直接调用公开的 Q_INVOKABLE 方法或槽。按钮禁用是展示状态，不能代替业务规则检查：increment() 自身仍判断上限，reset() 自身判断是否需要归零，从 C++ 直接调用也不能越过范围。

```text
用户点击
    → QML onClicked
    → VM 方法检查条件
    → 执行业务操作并发送属性通知
```

框架没有独立的执行前守卫复核层。业务条件及参数范围由 VM 和业务用例分别负责；点击处理器不要复制计数状态或直接修改业务字段。导航和确认 View 同样显式调用所属 VM 的方法。

## 4. 显式目标与对象替换

调用其他 VM 时在表达式中明确引用，不使用父链、窗口或方法名查找默认目标。下面的设计片段假定所属 View 已导入 HomeViewModel 类型：

```qml
property HomeViewModel otherViewModel: null

Button {
    text: "重置其他计数"
    enabled: root.otherViewModel !== null && root.otherViewModel.canReset
    onClicked: {
        if (root.otherViewModel)
            root.otherViewModel.reset()
    }
}
```

可空目标显式检查 null。替换 View 的 viewModel 或 otherViewModel 后，属性表达式跟随新对象；事件处理器执行时读取当前属性，不保存旧目标。不同 View 各自声明要引用的对象；不存在隐式动作作用域继承。

应用持有 VM，View 只借用。正常退出先销毁引擎与 View，再销毁 VM 树；动态页面先卸载旧 View，再释放其 VM。QML 绑定与事件处理器随 View 释放，不需要独立动作绑定对象。完整装配与所有权约定见 [ViewHost](ViewHost.md)。

## 5. 参数与键盘演示（第二批已实现）

Home 页面提供 `Q_INVOKABLE void add(int delta)` 与只读 `canAddTwo` 属性。VM 只接受正增量且结果不能超过 5；零、负数、超出剩余额度及极大值均拒绝，不赋值、不发送通知。先比较 `delta <= 5 - m_count` 再相加，避免有符号整数溢出；increment() 复用 add(1)，reset() 保持原行为。

“加 2”按钮显式绑定 canAddTwo 并调用 add(2)，计数 0～3 时可用，4～5 时禁用。canAddTwo 只在 bool 结果实际变化时通知，View 不重复计算业务范围。

```qml
Button {
    text: "加 2"
    enabled: root.viewModel !== null && root.viewModel.canAddTwo
    onClicked: { if (root.viewModel) root.viewModel.add(2) }
}
```

页面 Item 初始获得焦点，通过原生 Keys 处理未被控件消费的无修饰数字键 2：

```qml
Keys.priority: Keys.AfterItem
Keys.onPressed: (event) => {
    if (event.key === Qt.Key_2 && event.modifiers === Qt.NoModifier
            && !event.isAutoRepeat && root.viewModel && root.viewModel.canAddTwo) {
        root.viewModel.add(2)
        event.accepted = true
    }
}
```

处理成功后接受事件；自动重复、修饰键、不匹配按键及不可用操作保持未接受，允许后续接收者处理。快捷键读取当前 viewModel，不捕获旧 VM，不另存计数。数字输入先由获得焦点的 TextField 处理，因此在文本框按 2 只输入文字。按钮的原生空格点击继续可用，未消费的数字键再向页面传播。[Qt Keys 事件顺序](https://doc.qt.io/qt-6.8/qml-qtquick-keys.html)

点击空白处将焦点移回页面。示例使用 KeyNavigation 显式规定 Tab 顺序：增加 → 加 2 → 重置 → 文本框 → 增加；Shift+Tab 反向移动，禁用项自动跳过。仅 Tab 导航设置 BeforeItem，数字键业务处理仍使用 Keys.AfterItem；不依赖 macOS 默认是否允许 Tab 聚焦按钮。[Qt KeyNavigation](https://doc.qt.io/qt-6.8/qml-qtquick-keynavigation.html)

焦点、事件消费顺序和自动重复属于 View；业务输入是否合法属于 VM。本批没有新增框架输入组件。完整源码见 [HomeView.qml](../examples/minimal/CaliburnExample/qml/views/HomeView.qml)。

## 6. 验证边界

当前测试覆盖类型与初始属性注入、VM 通知和业务边界、真实增加/加 2/重置事件、上限禁用、VM 替换、键盘事件接受与传播、自动重复过滤、TextField 优先输入、按钮原生空格点击、Tab / Shift+Tab 导航，以及 C++ 所有权和引擎销毁顺序。自动重复用 QKeyEvent 显式注入，不以快速连续单击代替长按事件。

第二批通过 offscreen 与 Cocoa 两套 QML 集成测试，并单独运行实际示例验证按钮、数字键和焦点操作。第三批已加入生命周期与视图装配，第四批已完成 Home/Detail 导航。5A 重置确认已实现并完成本机验收，确认 View 显式调用确认 VM，默认焦点为取消，Enter/Space 执行当前按钮，Escape 无决定关闭，关闭后恢复有效焦点，见 [WindowManager](WindowManager.md)；5B Detail 退出确认/关闭守卫已实现并完成本机验收。5B 单项成员普通停用也检查守卫，集合型普通停用和内部切换不检查，父级生命周期普通停用不因此增加检查；请求入口已迁移为普通命名的 void 方法，调用方不能在方法返回后直接假定页面已切换。范围与证据见 [迭代实现计划](迭代实现计划.md#第五批阶段划分) 和 [第二批验收记录](第二批验收记录.md)。
