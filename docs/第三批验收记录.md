## 1. 交付范围

- ScreenViewModel：只读初始化/激活状态、同步 C++ 生命周期、protected 钩子；自动初始化、幂等、停用后关闭、关闭后重激活；关闭不删除对象，线程与重入诊断拒绝。
- ViewRegistry：继承约束的模板登记、精确元对象查询、URL 校验、重复与冲突处理、配置冻结；C++ 与每引擎单例共享进程映射，不持有 VM。原验收使用首次非空查询冻结；2026-10-07 调整为显式 freeze()，由 Bootstrapper 在 Configure 成功后调用，查询不再冻结。
- ViewHost：创建完成后加载、初始 typed VM 注入、同类型替换重建、同对象属性变化保留身份；QPointer 和 destroyed 通知确保目标销毁清空，旧连接不影响新目标。
- 无映射、资源/语法失败、required 属性缺失、VM 类型或注入身份不匹配、非 Item 根对象均清空内容并记录错误。宿主不调用生命周期、不拥有 VM。
- Home 承接唯一计数状态、文案、方法、守卫、按钮与键盘输入；Shell 保持 ApplicationWindow 和 home 借用属性，展示两者生命周期状态。主程序交接 QObject 父所有权，显式安排初始化、激活、关闭及销毁次序。

Conductor、详情导航、共享业务服务、弹窗、通用默认焦点恢复、异步加载与麒麟验收留在后续批次。

## 3. 实施修正与诊断

宿主与 Home 根对象采用 FocusScope（Item 子类），内部输入区域仍为普通 Item，避免外层 focus 覆盖页面焦点，又允许空白点击退出文本框焦点。替换集成测试先等待当前宿主 item 的 VM 身份匹配，再定位新控件，避免读取空对象或旧页面。

故意非法的 fixtures 作为原始资源，未纳入正式 QML 模块编译与 qmllint；语法错误夹具会在导入扫描和失败路径测试中产生预期诊断。失败路径测试保留 QWARN 输出供核查，正常路径检查引擎无警告。链接器仍有静态插件重复库提示，不影响成功构建。

## 4. 实际示例操作

本次应用从 /private/tmp 启动，不使用工作目录中的 QML。通过原生窗口操作及可访问状态核对，截图确认生命周期文字、计数、按钮和文本框布局。

| 操作 | 实际结果 |
| --- | --- |
| 启动 | Shell/Home 均已初始化、已激活；计数 0，重置禁用。 |
| 点击加 2，再按数字键 2 | 计数 0→2→4，加 2 禁用。 |
| 再按数字键 2 | 保持 4，不越界。 |
| 点击重置 | 回到 0，按钮状态恢复。 |
| 文本框按 2 | 文本输入 2，计数仍为 0。 |
| Tab 后按空格 | 焦点到增加，计数为 1。 |
| 连续两次数字键 2 | 计数为 3、5，增加和加 2 禁用。 |
| 重置并清空文本，点击 Home 非交互说明区域后按 2 | 页面恢复焦点，计数为 2，文本仍为空。 |
| 关闭窗口 | 应用进程退出码 0。 |

空白点击由 offscreen 与 Cocoa 的真实鼠标事件测试覆盖；原生操作另验证 Home 非控件区域走同一 MouseArea 的回焦路径。实体长按未单独计时，重复过滤由两套 QKeyEvent 集成测试验证。

首次 Cocoa 运行恰逢系统锁屏，窗口无法获得活动焦点；原生工具也报告自动解锁失败。恢复窗口访问后，原生操作和 Cocoa 重跑均通过，未用首次失败结果替代通过证据。系统输入法输出 mach port / CapsLock 日志，不影响最终结果。
