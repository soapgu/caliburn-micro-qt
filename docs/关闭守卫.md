# 关闭守卫与 CM 直接回调

5B 提供 Detail 退出确认和关闭守卫。本轮按 CM 3.2.0 精简为直接许可回调，已完成本机复验，见 [CM 精简验收记录](CM关闭守卫精简验收记录.md)；历史证据见 [5B 验收记录](5B验收记录.md)。

## 接口

```cpp
using CloseCallback = std::function<void(bool)>;

class IGuardClose {
public:
    virtual ~IGuardClose() = default;
    virtual void canClose(CloseCallback callback) = 0;
};

class ICloseStrategy {
public:
    virtual ~ICloseStrategy() = default;
    virtual void execute(const QList<ViewModelBase *> &items,
                         CloseCallback callback) = 0;
};
```

IGuardClose 是纯 C++ 接口，IID 为 Caliburn.Micro.Qt.IGuardClose/1.0；Screen 默认立即同意。普通 VM 可自行实现。ConductorBase 通过 shared_ptr<ICloseStrategy> 提供 closeStrategy/setCloseStrategy；传入 nullptr 恢复默认策略。execute 不再接受 QObject context，自定义策略需要同步迁移签名。

默认策略按快照顺序逐项检查，兼容立即和延后许可；遇到 false 继续检查余项，全部同意才交付 true，没有守卫的对象默认同意。QPointer 快照中已销毁对象计为拒绝，继续检查后续成员。循环推进同步结果，延后回调恢复推进；没有每次关闭的 Request、取消上下文、请求表、代次或重复回调保护。

## 使用约定

所有操作及守卫回调在应用主线程执行，守卫必须交付一次结果。等待期间由模态交互约束业务，不支持重叠请求、重复回调、修改参与成员、生命周期重入或替换策略。没有全局忙锁、队列、超时和工作线程调度，也不承诺旧许可失效、主动取消及多请求完成顺序。

Conductor 直接调用策略，结果为 true 时同步执行变更；QPointer 检查管理者和借用目标的存活状态，仅用于内存安全。策略在 execute 调用期间以局部 shared_ptr 保活；自定义异步策略自行持有求值状态，并保证回调最终交付或释放。

activateItem、deactivateItem、closeItem、tryClose 均为 void 请求，不带完成回调。激活结果使用 activationProcessed，实际停用/关闭使用 Screen.deactivated(close)；方法返回不表示已经关闭或删除。拒绝不改变成员、Parent、选择或 View，不发送成功关闭通知。

## 单项与集合

单项仅管理当前项。替换当前项及当前项普通停用/关闭检查守卫；canClose 与父级生命周期仅处理当前项。普通停用清空选择，保留旧对象的 QObject 父关系和逻辑 Parent，但不登记留存成员。业务可再次传入本 Conductor 接管过、仍有效且未关闭的旧对象；非当前旧对象的停用或关闭请求不处理。父级关闭不补发这些旧对象的关闭生命周期，最终由 QObject 父树兜底回收。

集合型切换和普通停用不检查守卫，只有成员关闭检查；canClose 检查全部成员。嵌套 Conductor 通过各自 canClose 递归检查。默认策略不提供部分关闭。父级普通停用与直接强制生命周期清理不检查许可。

新候选基础校验失败不移动调用方 unique_ptr；通过后由回调捕获的标准 RAII 所有权容器保存，许可通过才接管。拒绝、回调结束或释放时回收；管理者已销毁时不提交。等待期间禁止外部删除候选，不承诺管理者销毁时立即回收仍被外部回调持有的候选。已提交关闭的对象不得重新使用，不维护关闭对象登记表。

## Detail 与 Shell

Detail 注入当前 Shell 的 IWindowManager。活动时 goBack 调用 tryClose；canClose 使用 ConfirmActionViewModel 展示“离开详情／确定离开当前详情吗？”。窗口结果 true 允许关闭，false、空值、窗口忙或展示失败均拒绝。窗口失败先转换为 false，再交付许可，关闭执行异常不会被当成展示失败而再次交付。

Future 续接绑定 Detail 生命周期，停用或销毁时取消自己的弹窗；Detail 不保存守卫编号、回调表或旧结果代次。非活动但仍在集合中的 Detail 显式关闭仍检查许可。5A WindowManager 的单弹窗展示约束、内部请求管理及 Home 重置机制保持原样。

Shell 的 prepareCloseItem 在许可通过后补建缺失 Home；取消不调用工厂，工厂失败不移除 Detail。Home VM 与计数保留，Home View 每次新建。

## 异常与平台边界

守卫、策略、同步生命周期和准备钩子异常直接传播，已提交状态不回滚，不提供“异常转拒绝”或“许可后抛异常仍拒绝”政策。异步调用方负责在自己的 Qt 边界处理异常；Detail 在 Future 许可续接内记录关闭执行异常。

直接回调与检查顺序参考 [CM 3.2.0 Conductor](https://github.com/Caliburn-Micro/Caliburn.Micro/blob/3.2.0/src/Caliburn.Micro/Conductor.cs) 和 [DefaultCloseStrategy](https://github.com/Caliburn-Micro/Caliburn.Micro/blob/3.2.0/src/Caliburn.Micro/DefaultCloseStrategy.cs)。Qt 继续使用显式所有权、QPointer、View 卸载通知和 deleteLater，不照搬 .NET GC 或 WPF 通知时序。

窗口 QFuture/QPromise 只表达弹窗结果，生命周期仍同步；不引入嵌套事件循环。根窗口桥接已接入现有许可链，规则见下一节。

## 根窗口与根 VM 双向桥接

WindowManager::showWindow 为普通窗口（包括根窗口）建立私有 WindowConductor。原窗口关闭事件先拒绝，退出当前调用栈后调用根 canClose；许可通过再恢复关闭，本桥接不重复询问，原有 QML onClosing 仍可拒绝。实际关闭成功后由窗口服务执行一次根关闭生命周期。

Shell 集合检查全部成员，包括非活动 Detail。整窗关闭提交根生命周期，不调用成员 prepareCloseItem，不补建 Home、不先返回首页。取消、Escape、空结果、忙和展示失败均保留窗口与成员。Detail 使用中性“离开详情”文案，返回与整窗关闭共用。

无逻辑 Parent 的 tryClose 发送 closeRequested，桥接请求关联窗口关闭；未关联窗口时无操作。根直接完成 deactivate(true) 后反向关闭窗口，不再询问已完成的生命周期；普通停用不关闭窗口。同步生命周期失败不回滚，Bootstrapper 已记录的关闭尝试不重试。

窗口层仅吸收等待期间重复关闭动作，不恢复 Conductor 的并发协调。借用对象使用 QPointer，不保存临时关闭事件。aboutToQuit 和 Shutdown 先停用桥接，再执行根清理与单次 OnExit；直接 exit 和强制清理不等待许可。正常 Qt Quit 可经窗口关闭链；本机 Cocoa 菜单退出及 Cmd+Q 已通过实际验收，其他平台待验证。结果见 [根窗口验收](根窗口关闭守卫与生命周期验收记录.md)。

## 独立模态弹窗守卫

WindowManager 为独立弹窗复用 WindowConductor；按钮结果、Escape、标题栏和弹窗 tryClose 都检查弹窗 VM 的 canClose。拒绝或窗口 onClosing 拒绝时保留窗口，丢弃本次结果，Future 不完成。直接关闭生命周期使用反向桥接，不重复询问和执行。请求者失效、服务退出和资源清理直接结束弹窗，不等待交互守卫。

根退出先停用桥接并结束弹窗，再处理根生命周期与 OnExit，保证弹窗先于引擎释放。保留单弹窗限制，守卫内再次弹窗按忙状态拒绝。见 [窗口服务](WindowManager.md) 与 [独立模态窗口验收](独立模态窗口验收记录.md)。
